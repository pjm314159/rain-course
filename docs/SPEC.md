# 雨课堂签到助手（Web 复刻版）需求规格（SPEC）

> 版本：v0.3
> 日期：2026-09-26
> 参考：`course_helper` 项目（Flutter，`rain-course/course_helper`）
> 形态：网站（浏览器访问）
> 技术设计见 [DESIGN.md](./DESIGN.md)

---

## 1. 项目背景与目标

雨课堂的课堂签到依赖教师端展示的动态二维码，学生需要用微信扫描二维码完成签到。本项目旨在用 Web 网站复刻 `course_helper` 中的签到辅助功能，解决：

1. 在 PC / 平板等不方便掏手机的场景下完成签到；
2. 一次扫码，多人共享（通过 WebSocket 将二维码内容实时分发给同房间其他用户）；
3. 自动化签到流程，减少手动操作。

**非目标**：不复制雨课堂的课件、答题等其他功能；仅围绕「签到」场景；不做管理后台。

---

## 2. 用户与使用场景

| 角色 | 说明 | 典型场景 |
|------|------|----------|
| 普通用户（学生） | 已登录雨课堂账号 | 上课前打开网页，扫码或接收分享，完成签到 |

单角色系统，无管理员/教师端。

## 3. 功能需求

### 3.1 登录模块（F1）

复刻 `course_helper` 的雨课堂登录能力，Web 端登录后由后端持有会话凭证。

#### 3.1.1 登录方式（旧项目已确认的实现，三种方式**均为必做**）

- **手机号 + 密码登录**：`POST /api/v3/user/login/app`（`type=2`）；**需携带有效 `ticket`/`randstr`**（同短信登录的验证码组件，旧项目密码登录前也弹验证码）；
- **短信验证码登录**（必做）：`POST /api/v3/user/code/send` → `POST /api/v3/user/code/verify`；
  - **已实测确认（2026-09-26，`scripts/test_yk_login.py`）**：空票据被拒，必须携带有效 `ticket`/`randstr`；
  - 获取方式：前端接入**腾讯验证码 Web JS SDK**（`TJCaptcha.js`，AppId 复用雨课堂的 `2091064951`，接入文档 <https://cloud.tencent.com/document/product/1110/36841>），用户通过挑战后回调返回票据，随请求透传；
  - ticket 校验由雨课堂服务端用其 `AppSecretKey` 完成，本站仅透传，**不需要任何腾讯云凭证**；ticket 一次性且短时效，须在挑战通过后立即使用。
- **微信扫码登录**（必做，**复用雨课堂自己的实现**）：`GET /api/v3/user/login/pre-info` 直接返回二维码图片（`qrImage`）与 `token` → 前端展示图片 → `POST /api/v3/user/login {token}` 30s 服务端长轮询，50001 = 扫码超时（自动刷新二维码重试）；
  - **无需本站拥有微信公众号/开放平台**——扫码页由雨课堂侧实现，我们仅展示其二维码并轮询登录结果。

#### 3.1.2 会话管理

- 登录成功后，后端保存雨课堂会话（`csrftoken` / `sessionid` / `x-uid` cookie，签到后的 `Bearer` token），并与本站会话绑定；
- 前端保存本站登录态，刷新不掉线；
- **本站会话有效期：14 天滑动续期**（每次活跃访问刷新有效期），到期后需重新登录；登录凭证为签名 cookie（HMAC，防篡改），校验只需验证签名，无服务端存储；
- 14 天的依据：已抓包确认雨课堂 `sessionid` 有效期 14 天（`csrftoken` 1 年）——本站会话与雨课堂会话对齐，一次登录期内两边凭证同时有效，避免"站内还在登录、签到却要重登"的割裂体验；
- 雨课堂凭证仅存后端内存（不落盘）：**服务重启后需要重新登录**（接受此代价换取零存储依赖）；
- 注意：雨课堂自身的服务端会话可能提前过期（`sessionid` 的有效期需抓包确认，不受本站控制），届时本站仍处于登录态，但签到操作会引导重新完成雨课堂登录；
- 支持退出登录（清除两端凭证）。

#### 3.1.3 异常处理

- 账号密码错误、验证码错误 → 明确提示；
- 雨课堂会话过期 → 前端收到统一错误码，引导重新登录（旧项目启动时以 `user_info` 探测失效，我们采用请求时惰性检测）；
- 登录请求需有超时与失败重试限制（防刷）。

#### 3.1.4 验收标准

- [ ] 正确凭证可登录成功并进入主界面；
- [ ] 三种登录方式（密码 / 短信验证码 / 微信扫码）全部可用；
- [ ] 短信/密码登录均通过腾讯验证码组件获取票据后成功（`scripts/test_yk_login.py` 已验证的流程）；
- [ ] 微信扫码登录二维码过期后自动刷新，扫码成功后自动进入主界面；
- [ ] 错误凭证有明确错误提示；
- [ ] 会话过期后操作接口返回统一错误并跳转登录页；
- [ ] 14 天内不活跃才过期；
- [ ] 退出登录后凭证被清除。

### 3.2 扫码签到模块（F2）

复刻 `course_helper` 的二维码签到：识别雨课堂签到二维码并调用签到接口。

#### 3.2.1 二维码内容（旧项目已确认）

- 雨课堂签到二维码内容是 **URL**（动态码）；
- 签到两步流程：`POST /api/v3/app/scan {"url": <二维码URL>}` 解析出 `lessonId` → `POST /api/v3/lesson/checkin` 完成签到；
- 错误码 **51203** 表示动态二维码过期；
- **内容必须经过严格的安全校验后才可被处理**（域名白名单等，详见 §4 与 DESIGN.md §5）。

#### 3.2.2 扫码方式（两级策略）

**首选：微信扫一扫（微信 JS-SDK `wx.scanQRCode`）**

- 在微信内置浏览器中打开网页时，通过 JS-SDK 调起微信原生扫码；
- 需要：已认证的微信公众号 + JS-SDK 权限签名（后端提供签名接口）。

**降级：浏览器原生相机扫码**

- 优先使用 `BarcodeDetector` API，不支持时降级到 JS 解码库 + `getUserMedia`；
- 需处理相机权限拒绝、无摄像头设备（PC）等场景。

**补充：上传图片识别**

- 支持上传二维码截图，前端本地识别二维码内容后走统一签到流程；
- 图片仅在浏览器内解码（`BarcodeDetector` 优先、`@zxing/browser` 降级），**不上传服务器**（对齐 §4 隐私要求）；
- 单张图片 ≤ 5MB；图片中未识别出二维码时明确提示。

**兜底：手动输入**

- PC 场景支持手动输入/粘贴二维码内容或签到链接。

#### 3.2.3 签到流程

1. 用户进入「扫码签到」页；
2. 选择扫码方式（微信 / 相机 / 手动输入）；
3. 获得二维码 URL 后提交后端；
4. 后端校验域名白名单 → 调用 `scan` + `checkin`（携带 3.1 保存的会话）；
5. 返回签到结果（成功 / 已签过 / 已过期 / 失败原因）。

#### 3.2.4 异常处理

- 二维码内容非白名单 URL 或无法解析 → 提示"不是有效的雨课堂签到码"；
- 签到码过期（51203）→ 提示过期，可配合分享功能获取最新码；
- 重复签到 → 幂等处理，提示已签到；
- 相机被占用 / 权限拒绝 → 引导切换到手动输入或分享方式；
- 上传图片中未识别出二维码 / 图片超限（> 5MB）→ 明确提示，不影响其他签到方式。

#### 3.2.5 验收标准

- [ ] 微信内打开可用 `wx.scanQRCode` 完成签到；
- [ ] 普通浏览器可用相机扫码完成签到；
- [ ] 可上传二维码截图完成签到（图片本地识别，不上传服务器）；
- [ ] 无相机环境可手动粘贴内容完成签到；
- [ ] 非白名单域名的二维码内容被拒绝且不发起任何外部请求；
- [ ] 各类失败场景均有明确反馈。

### 3.3 分享房间模块（F3，WebSocket）

复刻 `course_helper` 的"分享"能力：一人扫到二维码后，通过 WebSocket 房间实时分发给其他用户，实现"一人扫码、多人签到"。

#### 3.3.1 房间机制

- 用户可**创建房间**，获得房间号（短 ID / 数字暗号，便于口头传播）；
- 其他用户输入房间号**加入房间**；
- **房间密码（F3.1）**：创建时可选设置房间密码；
  - 设置密码的房间，加入时必须提供正确密码；
  - 密码房间**不出现在广场（F4）**；
  - 未设置密码的房间为公开房间，凭房间号即可加入；
- **房间关联信息（可选）**：创建房间时可附加课程信息——课程名称、上课地点、教师、上课时间、班级，全部字段可选，不填不影响功能；公开房间的关联信息展示在广场，密码房间仅房间内成员可见；
- 房间内成员实时接收扫码者推送的二维码内容/签到参数；
- 房主（创建者）可关闭房间；**房主退出/断线不解散房间**（类微信策略）：房主身份保留，重新连接后自动恢复，详见 §3.3.3；

#### 3.3.2 消息协议

见 DESIGN.md §4（join / joined / join_need_password / leave / share_qr / qr_update / sign_result / plaza_update / error / heartbeat）。

#### 3.3.3 房间规则与资源上限（防无上限占用导致 OOM）

资源类上限均为硬性要求，所有上限值可在后端配置中调整：

- **房间数量上限**：全局同时存在的房间数 ≤ 100；每用户同时创建房间数 ≤ **5**；达到上限时创建请求被拒绝并明确提示；
- **房间人数上限**：单房间 ≤ 50 人；
- **房主策略（类微信）**：房主退出或断线**不解散房间**，房主身份保留，重新连接后自动恢复；房间关闭仅由房主主动操作或生命周期到期触发；
- **房间生命周期**：
  - 创建时可**自定义生命周期**（精确到分钟，可选）；
  - 允许设为**永久**；
  - 默认 4 小时（覆盖一节课）；
- **无消息自动删除**：房间连续 **14 天**无任何消息即自动删除回收——**永久房间同样受此约束**；实际过期时间 = min(自定义生命周期, 最后一条消息时间 + 14 天)；
- **消息大小上限**：单条消息（含二维码内容）≤ 2KB，超限直接拒绝；
- **消息频率上限**：单连接发送 ≤ 30 条/分钟，超限断开连接（close code 4008）；
- **消息队列（FIFO）**：每频道最多保留 **100 条**消息（本质为 URL，内存开销可接受），超过 100 条删除最旧的、加入新的，保证新加入/重连成员**能收到历史消息**；
- **消息有效期**：每条消息带生命周期（默认 1 小时，房主可自定义，上限 1 小时）；过期消息**直接删除**，不再展示、不可签到；
- **广播通道容量有界**（满则丢弃最旧），杜绝无界堆积；
- **单客户端单连接**：同一用户的多个页面/标签页共享**一条 WebSocket 连接**（SharedWorker 复用），连接数不随标签页增长；
- **心跳保活**：客户端 **30s pong**——服务端 30s 一次心跳，客户端须在 30s 内应答，假死连接及时剔除；
- 服务端仅做转发与房间管理，**不持久化**消息内容（内存态）。

#### 3.3.4 验收标准

- [ ] 两个浏览器分别登录，A 创建房间、B 加入，A 扫码后 B 在 1 秒内收到二维码内容；
- [ ] B 断网重连后自动回到房间并收到未过期历史消息；过期消息已删除不再出现；
- [ ] 同一用户多个标签页只存在一条 WebSocket 连接，消息在各标签页同步；
- [ ] 客户端 30s pong 心跳保活，假死连接被及时剔除；
- [ ] 房主退出/断线后房间不解散，重连后房主身份恢复；
- [ ] 单频道消息队列 ≤ 100 条上限生效（FIFO 淘汰最旧），过期消息被删除，房间存储有界；
- [ ] 房间 14 天无消息（含永久房间）被自动删除；
- [ ] 自定义生命周期与永久选项生效；
- [ ] 房间关联信息可选填写，公开房间的关联信息在广场可见；
- [ ] 带密码房间：密码错误 / 缺失时无法加入；密码正确可加入；不出现在广场中；
- [ ] 全局房间数、单人建房数、房间人数、消息大小/频率达到上限时均被拒绝且有明确提示；
- [ ] 房间过期/关闭后资源被回收；
- [ ] 恶意消息（非法格式、超频）被服务端拒绝。

### 3.4 广场模块（F4）

提供"广场"页面，展示当前所有**公开（无密码）房间**，方便用户发现并加入。

#### 3.4.1 功能点

- 广场列表展示每个公开房间的：房间号、房间名、当前人数、创建时间，以及（若填写）关联课程信息；
- 列表实时性：新增房间、房间关闭、人数变化能以较短延迟反映（WS 推送，见 DESIGN.md）；
- 点击房间可直接申请加入；
- 密码房间绝不出现（列表与计数中均不可见，不可通过猜测列表接口参数获取）；
- 未登录用户不可见广场。

#### 3.4.2 验收标准

- [ ] 公开房间创建后出现在广场，关闭/过期后消失；
- [ ] 人数变化能反映到广场；
- [ ] 任何接口都无法枚举到密码房间；
- [ ] 未登录用户无法获取广场数据。

### 3.5 查看当前课程（F5）

旧项目（`course_helper`）已确认具备该功能（课程列表页 + `GET /api/v3/classroom/on-lesson` 接口），复刻为辅助模块：登录后展示用户"正在上课"的课程，帮助快速定位需要签到的课堂。

#### 3.5.1 功能点

- 展示正在上课的课程列表：课程名、教师、课堂名（班级）、课程头像；
- 数据取自雨课堂 `GET /api/v3/classroom/on-lesson` 与 `GET /v/course_meta/learning_list/` 的交集（对齐旧项目 `getCoursesList()` 逻辑），实时透传，本站不落库；
- 支持手动刷新；无正在上课课程时显示空态。

#### 3.5.2 验收标准

- [ ] 登录后可见正在上课的课程列表（课程名/教师/课堂名/头像）；
- [ ] 无正在上课课程时有空态提示；
- [ ] 雨课堂会话过期时展示统一登录引导。

## 4. 安全需求

| 项 | 要求 |
|----|------|
| 二维码内容域名校验（重点） | 二维码内容为 URL，后端处理前必须严格校验：scheme 必须为 HTTPS，域名必须命中雨课堂域名白名单（源码 `serverBaseUrlMap`：`www/pro/changjiang/huanghe.yuketang.cn` 等，固化为后端配置）；非白名单内容一律拒绝，**绝不向其发起请求**（防 SSRF / 钓鱼转发） |
| 会话 | 本站凭证 HTTPS 传输，14 天滑动过期（与雨课堂 `sessionid` 14 天对齐）；签名 cookie 防篡改（校验无需查库）；雨课堂凭证仅存后端内存，不落盘、不落日志；WS 连接需校验本站会话 |
| WS 资源 | lobby（未加入房间）连接闲置 10 分钟由服务端主动断开，前端按需重连；心跳判死；连接数上限保护 |
| 房间密码 | 服务端校验，错误次数限速；密码仅存内存，不落日志 |
| 限流 | 登录、签到、建房、加房等接口按 IP/用户限流 |
| 资源上限 | 房间数量/人数、消息大小/频率/存量全部有硬上限（见 §3.3.3），任何输入都无法导致内存无界增长 |
| 隐私 | 不持久化用户雨课堂凭证、二维码内容、房间数据 |
| 输入校验 | 所有接口入参有类型/长度/频率校验 |
